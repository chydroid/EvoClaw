### 2.1 Webhook 系统 (IncomingWebhookManager)

#### 功能说明

实现外部系统通过 HTTP 请求触发 EvoClaw 内部动作的 Webhook 系统，对标 OpenClaw 的完整 hooks 系统。支持 URL 模式匹配、Token 认证、Action Handler 机制和事件日志。

#### 实现思路

参考 OpenClaw 的 `hooks/` 路由系统，设计 `IncomingWebhookManager` 类：

1. **端点注册**：通过 `register()` 方法注册 Webhook 端点，包含路径、HTTP 方法、认证 Token、关联动作
2. **URL 模式匹配**：`matchEndpoint()` 支持段级通配符 (`/hooks/github/*`) 和尾部通配符 (`/hooks/events/*`)
3. **Token 认证**：`authenticate()` 验证 `Authorization: Bearer <token>` 或 `X-Webhook-Token` 头
4. **Action Handler**：可插拔的动作处理器，将 Webhook 请求映射为内部事件
5. **事件日志**：记录所有 Webhook 触发事件，支持查询和统计

#### API 文档

**创建 Webhook 端点**

```
POST /api/webhooks
Content-Type: application/json

Request Body:
{
  "id": "github-push",           // 必填，唯一标识
  "path": "/hooks/github",       // 必填，URL 路径
  "method": "POST",              // 必填，POST 或 GET
  "authToken": "secret-token",   // 可选，认证 Token
  "action": "github.push",       // 必填，关联动作名
  "description": "GitHub push events",  // 可选
  "enabled": true                // 可选，默认 true
}

Response 201:

  "success": true,

}
```

### 2.2 模型故障转移增强 (Model Failover Enhancement)

#### 功能说明

增强 LLM 模型调用的可靠性和容错能力，对标 OpenClaw 的完整 Model Failover 机制。实现 Fallback Chain、API Key 轮换、半开断路器、健康评分和动态优先级。

#### 实现思路

参考 OpenClaw 的 `ModelFailover` 和 Hermes Agent 的多 Provider 管理，在现有 `ModelFailoverManager` 基础上扩展：

1. **Fallback Chain**：每个 Provider 可配置有序的降级链，当主 Provider 不可用时自动切换到备用
2. **API Key 轮换**：支持多 API Key 配置，检测到 429/限流时自动切换到下一个 Key
3. **半开断路器**：断路器从 open → half-open 时允许有限探测请求通过，渐进恢复
4. **健康评分**：3 维评分系统（成功率 0.5 + 延迟 0.3 + 错误率 0.2），实时反映 Provider 健康状态
5. **动态优先级**：基于健康评分自动调整 Provider 优先级，公式：`baseOrder * 100 + (100 - healthScore) + circuitPenalty`

**获取故障转移状态**

```
    "totalFailures": 23,
    "avgOverallLatencyMs": 850,
    "avgHealthScore": 87,
    "providers": [
      {
        "id": "openai-primary",
        "circuitState": "closed",
        "healthScore": 95,
        "dynamicPriority": 5,
        "currentKeyIndex": 0,
        "fallbackChain": ["anthropic-backup", "local-llm"]

```

**重置断路器**

#### 使用示例

```typescript
import { ModelFailoverManager, FailoverProvider } from "@evoclaw/agent";

const failover = new ModelFailoverManager({
  failureThreshold: 5,
  resetTimeoutMs: 30000,
  halfOpenProbeLimit: 1,
  healthScoreSuccessWeight: 0.5,
  healthScoreLatencyWeight: 0.3,
  healthScoreErrorWeight: 0.2,
});

// 注册带 Fallback Chain 的 Provider
failover.registerProvider({
  id: "openai-primary",
  name: "OpenAI GPT-4",
  enabled: true,
  order: 1,
  healthCheck: async () => { /* ... */ return true; },
  apiKeys: ["sk-key1", "sk-key2", "sk-key3"],
  fallbacks: ["anthropic-backup", "local-llm"],
});

failover.registerProvider({
  id: "anthropic-backup",
  name: "Anthropic Claude",
  enabled: true,
  order: 2,
  healthCheck: async () => { /* ... */ return true; },
  fallbacks: ["local-llm"],
});

// 使用 executeWithFallback 自动遍历降级链
try {
  const result = await failover.executeWithFallback(
    "openai-primary",
    async (providerId, apiKey) => {
      return await callLLM(providerId, apiKey, prompt);
    }
  );
} catch (err) {
  console.error("All providers failed:", err);
}

// 手动获取当前 API Key
const apiKey = failover.getCurrentApiKey("openai-primary");

// 查看健康状态
const health = failover.getHealth("openai-primary");
console.log(`Health score: ${health?.healthScore}, Circuit: ${health?.circuitState}`);

// 获取优先级排序的 Provider 列表
const prioritized = failover.getPrioritizedProviders();
```

### 2.3 技能策展器 (SkillCurator)

#### 功能说明

实现自我改进的技能闭环系统，灵感来自 Hermes Agent 的 Curator 机制。能够从成功方案中自动提取技能、基于执行反馈自动改进技能、管理技能版本演进。

#### 实现思路

参考 Hermes Agent 的 `Curator` 系统，设计 `SkillCurator` 类：

1. **技能提取**：`extractSkillFromSolution()` 从成功的任务-方案对中自动提取 SKILL.md，自动推导名称/描述/指令/触发器/关键词/分类/依赖
2. **技能改进**：`improveSkill()` 基于执行结果和用户反馈改进技能：
   - 失败分析：超时→增加时间限制、权限→检查沙箱策略、资源缺失→添加前置检查
   - 负面反馈分析：速度→优化效率、准确性→增加验证、易用性→简化步骤
   - 正向反馈整合：将最佳实践写入技能指令
3. **版本管理**：每次改进自动递增 patch 版本号，记录版本链和变更历史
4. **弃用机制**：`deprecateSkill()` 标记技能为弃用状态，自动禁用

#### API 文档

**获取技能演进历史**

#### 使用示例

```typescript
import { SkillCurator } from "@evoclaw/skills";

const curator = new SkillCurator(registry, eventBus);

// 从成功方案中提取技能
const skill = await curator.extractSkillFromSolution(
  "翻译英文文档为中文",
  "1. 读取文件 2. 调用翻译API 3. 写入结果",
  { source: "user-request" }
);

// 基于执行失败改进技能
const improvedSkill = await curator.improveSkill(
  skill.id,
  {
    success: false,
    errors: ["timeout: execution exceeded 60s"],
    duration: 65000,
    output: null,
  },
  "翻译速度太慢了"
);

// 基于正向反馈改进技能
await curator.improveSkill(
  skill.id,
  { success: true, errors: [], duration: 5000, output: "翻译完成" },
  "翻译质量很好，但希望能保留原文格式"
);

// 查看技能演进历史
const evolution = curator.getSkillEvolution(skill.id);
console.log(`版本链: ${evolution.versions.map(v => v.version).join(" → ")}`);

// 弃用技能
await curator.deprecateSkill(skill.id, "已被更好的翻译技能替代");

// 查看策展统计
const stats = curator.getEvolutionStats();
// { totalTracked: 5, totalExtractions: 3, totalImprovements: 7, totalDeprecations: 1, averageVersionsPerSkill: 2.2 }
```

### 3.2 WebSocket 协议标准化 (TypeBox Schema)

#### 功能说明

实现基于 TypeBox Schema 的类型化 WebSocket RPC 协议，对标 OpenClaw 的 JSON-RPC 风格请求/响应/事件协议。

#### 架构设计

```
packages/gateway/src/ws/
├── ws-protocol.ts          # 协议定义 (TypeBox Schema)
├── ws-server.ts            # WebSocket 服务器
├── ws-client-manager.ts    # 客户端连接管理
├── ws-request-handler.ts   # 请求路由与处理
└── ws-event-broadcaster.ts # 事件广播器
```

#### 接口规范

```typescript
import { Type, Static } from "@sinclair/typebox";

const WSRequestSchema = Type.Object({
  id: Type.String(),
  method: Type.String(),
  params: Type.Optional(Type.Record(Type.String(), Type.Unknown())),
  timestamp: Type.Number(),
});

const WSResponseSchema = Type.Object({
  id: Type.String(),
  result: Type.Optional(Type.Unknown()),
  error: Type.Optional(Type.Object({
    code: Type.Number(),
    message: Type.String(),
  })),
  timestamp: Type.Number(),
});

const WSEventSchema = Type.Object({
  event: Type.String(),
  data: Type.Unknown(),
  source: Type.Optional(Type.String()),
  timestamp: Type.Number(),
});

type WSRequest = Static<typeof WSRequestSchema>;
type WSResponse = Static<typeof WSResponseSchema>;
type WSEvent = Static<typeof WSEventSchema>;

interface WSProtocolHandler {
  methods: Map<string, {
    schema: typeof WSRequestSchema;
    handler: (params: Record<string, unknown>) => Promise<unknown>;
  }>;
  events: Map<string, {
    schema: typeof WSEventSchema;
  }>;
}
```

#### API 端点

```
WebSocket /ws                    # 主 WebSocket 连接
  → request:  { id, method, params, timestamp }
  ← response: { id, result, error, timestamp }
  ← event:    { event, data, source, timestamp }

支持方法:
  chat.send       # 发送聊天消息
  chat.history    # 获取聊天历史
  skills.list     # 列出技能
  skills.execute  # 执行技能
  system.status   # 系统状态

```

## 七、与现有架构的一致性

### 7.1 技术栈保持一致

| 维度 | 现有方案 | 新增功能方案 |
|------|---------|------------|
| 语言 | TypeScript (strict) | TypeScript (strict) |
| 构建 | tsc | tsc |
| 测试 | Vitest | Vitest |
| 包管理 | pnpm 10 monorepo | pnpm 10 monorepo |
| 服务注册 | ServiceRegistry | ServiceRegistry |
| 事件总线 | EventBus | EventBus |
| HTTP 框架 | Express | Express |
| 日志 | console.log/warn/error | console.log/warn/error |

### 7.2 代码规范保持一致

- 所有新增类通过 `ServiceRegistry` 注册服务
- 所有事件通过 `EventBus` 发布/订阅
- API 路由统一在 `ProtocolAdapter.mountREST()` 中注册
- 错误处理使用 `handleError()` 统一格式
- 类型定义与 `@evoclaw/core` 包的类型系统兼容
- 导出通过各包的 `index.ts` 统一管理

### 7.3 安全规范保持一致

- 所有 API 端点通过 `AuthProvider` 中间件鉴权
- 输入验证：类型检查 + 长度限制 + 白名单校验
- 路径遍历防护：拒绝包含 `..`、`/`、`\` 的路径参数
- 命令注入防护：正则过滤危险模式
- Cookie 安全：`httpOnly: true`，`sameSite: "strict"`
- JWT 密钥：启动时检测弱密钥并警告
