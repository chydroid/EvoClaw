# 国内用户行为数据同步至新加坡数据中台 AI 训练项目
## 跨境数据合规分析报告

**版本**: v1.0 | **日期**: 2026-11-08 | **负责人**: 数据合规负责人
**适用场景**: 国内用户行为数据 → 新加坡数据中台 → AI 模型训练

---

## 一、核心摘要

本项目涉及将中国境内收集的**用户行为数据**（含点击流、搜索词、画像标签等）跨境传输至**新加坡**用于 AI 模型训练，属于典型的**跨境数据出境**场景。核心合规挑战：

1. **法律依据复杂**：同时受中国《个人信息保护法》(PIPL)、《数据安全法》(DSL)、《网络安全法》(CSL)、新加坡 PDPA 双方法域约束；
2. **路径选择关键**：出境须完成"三选一"法定路径（安全评估 / 标准合同 / 认证）+ 新加坡侧 PDPA 合规；
3. **敏感字段高危**：含生物识别、位置轨迹、精确搜索意图的字段属**敏感个人信息**，须单独同意 + 加密 + PIA；
4. **用户权利跨境实现**：删除/可携带/撤回同意须跨境闭环执行，技术架构须支持；
5. **监管红线明确**：2025 年 9 月公安/网信部门首次对未履行 PIA 义务的 AI 数据公司开出行政处罚，PIA 缺失已成执法热点。

## 二、适用法规矩阵

### 2.1 中国大陆侧

| 法规 | 关键条款 | 对本项目的约束 | 执法主体 |
|------|---------|---------------|----------|
| **《个人信息保护法》(PIPL, 2021.11.1 施行)** | 第 38 条：向境外提供个人信息须完成"安全评估 / 标准合同 / 认证"之一；第 39 条：境外接收方须满足同等保护水平；第 40 条：重要数据不得出境；第 55-56 条：处理敏感个人信息须 PIA | 行为数据含 PI，出境须选法定路径；AI 训练用途变更需重新评估 | 网信办 + 地方网信部门 + 公安机关 |
| **《数据安全法》(DSL, 2021.9.1 施行)** | 第 31 条：重要数据出境须安全评估；第 32 条：跨境数据传输依《网络安全法》 | 若行为数据被认定"重要数据"（如规模化精准画像），出境须走**国家网信办安全评估** | 国家数据局 |
| **《网络安全法》(CSL, 2017.6.1 施行)** | 第 37 条：关基运营者(CII)数据本地化；第 40-42 条：个人信息保护基本要求 | 若公司为 CII 运营者，**数据不得出境**，只能在境内完成 AI 训练 | 国家网信办 + 公安部 |
| **《数据出境安全评估办法》(2022.9.1 施行)** | 100 万人以上 PI 或 1 万条敏感 PI 须申报 | 用户量大（>100 万）或含敏感 PI 必须走**安全评估** | 国家网信办 |
| **《个人信息出境标准合同办法》(2023.6.1 施行)** | 100 万以下 PI 且非 CII 可签标准合同向境外提供 | 中小数据量场景可选**标准合同路径** | 地方网信部门备案 |
| **《促进和规范数据跨境流动规定》(2024.3.22 施行)** | 自贸区/敏感行业豁免条款；非 CII 100 万以下 PI 可免申报 | 部分场景可简化，但**重要数据仍须评估** | 国家网信办 |
| **《生成式人工智能服务管理暂行办法》(2023.8.15 施行)** | 第 7 条：训练数据合法性；第 12 条：不得非法获取他人 PI 用于训练 | AI 训练用途本身即属 PIPL 第 13 条"法定事由"，须有合法基础 + 用户告知同意 | 网信办 |

> **执法热点提示**：2025 年 9 月，公安部门与网信部门通报**两起 PIA 缺失行政处罚案例**（人脸类敏感 PI + 自动售货机人脸采集），为 PIPL 施行以来首批 PIA 执法案例，AI 训练场景的 PIA 要求已被重点执法。

### 2.2 新加坡侧

| 法规 | 关键条款 | 对本项目的约束 | 执法主体 |
|------|---------|---------------|----------|
| **PDPA (Personal Data Protection Act 2012, 2020 修订)** | Section 26：**Transfer Limitation Obligation** —— 跨境传输 PI 须确保接收方所在国/地区提供"相当于 PDPA"的保护，或取得个人明示同意/合同义务 | 新加坡中台接收中国 PI 须：① 签订标准数据传输协议(STDA 模板)，或② 获取个人明示同意 | PDPC (Personal Data Protection Commission) |
| **PDPC Advisory Guidelines on Cross-Border Data Transfers** | 要求合同覆盖 7 大义务（安全、可携带、访问、删除、问责、子处理者、投诉） | 中新数据中台协议须覆盖 PDPC 7 大义务 | PDPC |
| **PDPA 数据主体权利** | Section 22：删除请求；Section 23：更正；Section 26 删除权跨境联动 | 中国用户行使删除权须同步删除新加坡中台数据 | PDPC |
| **Model AI Governance Framework (2024)** | AI 数据治理 5 支柱（合法性、透明性、问责制、可审计性、安全性） | AI 训练数据全链路须可审计、可追溯 | IMDA + PDPC |

### 2.3 跨境数据流动"三选一"路径总览（PIPL 第 38 条）

```
          ┌───────────────────────────────────────────┐
          │   PIPL 第 38 条 跨境传输三种法定路径      │
          ├───────────────────────────────────────────┤
          │ ① 国家网信办 安全评估   (大规模/重要数据) │
          │ ② 个人信息 标准合同     (中小数据量)      │
          │ ③ 个人信息 保护认证     (自贸区/跨法域)   │
          └───────────────────────────────────────────┘
```

> **关键原则**：三种路径**互斥**，项目须选定一条并执行到底。新加坡中台接收方须同时满足 PDPA 接收义务，形成"中国侧出境合规 + 新加坡侧接收合规"双层结构。

## 三、数据分级：敏感 vs 可匿名化

### 3.1 用户行为数据字段分级表

| 数据类别 | 典型字段 | 分级 | 出境路径 | 同意要求 | 加密要求 | 备注 |
|---------|---------|------|---------|---------|---------|------|
| **直接标识符** | 手机号、身份证号、邮箱、用户 ID | 1 级（核心 PI） | 须路径 | 单独同意 | AES-256 静态 + TLS 1.3 传输 | 建议 PII 字段哈希脱敏 |
| **生物识别** | 人脸、指纹、声纹 | **敏感 PI**（PIPL 第 28 条） | 须安全评估 | **单独同意** + PIA | **强制加密** + 访问审计 | 2025.9 执法热点，PIA 缺失已被处罚 |
| **位置轨迹** | GPS 经纬度、Wi-Fi 探针轨迹 | **敏感 PI** | 须安全评估 | **单独同意** + PIA | 强制加密 | 精确到 100m 以内属敏感 |
| **搜索/点击流** | 搜索关键词、点击 URL、停留时长 | 1 级（PI） | 依量级 | 概括同意 | TLS 传输 | 高频行为可聚合去标识化 |
| **精确意图标签** | 疾病/婚恋/宗教/政治倾向标签 | **敏感 PI** | 须安全评估 | **单独同意** + PIA | 强制加密 | AI 训练用途须重新评估 |
| **设备信息** | IMEI、MAC、设备型号 | 1 级（PI） | 依量级 | 概括同意 | TLS | 可去标识化 |
| **消费行为** | 订单金额、品类、频次 | 1 级（PI） | 依量级 | 概括同意 | TLS | 可去标识化 + 差分隐私 |
| **聚合统计量** | 日活、转化率、品类占比 | 3 级（匿名化） | 可自由出境 | 无需同意 | 无强制 | 已去标识化不可复原 |
| **日志审计数据** | 操作日志、访问轨迹 | 2 级 | 依场景 | 无需 | TLS | 可裁剪出境 |

### 3.2 出境数据最小化原则

**建议出境白名单（脱敏后）**：
- ✅ 行为序列（点击流聚合、停留时长桶）—— 去标识化，去除精确 ID
- ✅ 品类偏好标签（粗粒度）—— 差分隐私处理
- ✅ 聚合统计量（日/周级）
- ✅ 模型梯度（federated 联邦学习场景下）
- ❌ 不直接出境手机号、身份证、人脸、精确位置
- ❌ 不直接出境疾病/婚恋/宗教/政治标签（如必要须单独同意 + PIA）

## 四、出境路径选型对比

### 4.1 三条路径对比表

| 维度 | ① 安全评估 | ② 标准合同 | ③ 保护认证 |
|------|-----------|-----------|-----------|
| **法律依据** | PIPL 第 38(1)条 + 《数据出境安全评估办法》 | PIPL 第 38(2)条 + 《个人信息出境标准合同办法》(2023.6.1) | PIPL 第 38(3)条 + 个人信息保护认证（自贸/跨法域） |
| **适用条件** | 100 万人以上 PI 或 1 万条敏感 PI；CII 运营者；重要数据 | 非 CII、100 万人以下 PI、10 万人以下敏感 PI | 自贸区试点、跨法域数据流动、特定行业 |
| **审批/备案机关** | 国家网信办 | 省级网信部门备案（30 天） | 认证机构 + 备案 |
| **审批时长** | **60-90 天**（含公示） | **7-14 天**（合同签署 + 备案） | 依认证机构 |
| **年度续期** | 每 3 年评估 | 合同 3 年 + 重大变更须重签 | 认证 3 年 |
| **直接成本** | **¥50-150 万**（律所 + 评估 + 公示） | **¥10-30 万**（律所 + 备案） | **¥30-80 万**（认证机构费） |
| **隐性成本** | 高管配合、材料准备、整改周期 | 低 | 中 |
| **合规稳健度** | 最高（网信办背书） | 中（备案即可，无行政背书） | 高（跨法域互认） |
| **适用本项目** | **用户量 >100 万或含敏感 PI → 必须** | 中小数据量、非 CII 场景 | 自贸区/跨法域专项 |
| **监管风险** | 低 | 中（备案可被撤回） | 低 |

### 4.2 场景化路径推荐

- **场景 A：用户量 >100 万 + 含人脸/位置/精确标签** → 走**安全评估**（①）
- **场景 B：用户量 <100 万 + 无敏感 PI + 非 CII** → 走**标准合同**（②）
- **场景 C：数据含重要数据或 CII** → 安全评估（①）或**禁止出境**
- **场景 D：自贸区业务** → 可申请**认证**（③）+ 豁免简化

> **本项目默认假设**：用户行为数据规模较大、含部分敏感标签 → 推荐**安全评估路径（①）**，同时签订**新加坡侧 STDA 标准数据传输协议**形成双层合规。

## 五、技术措施

### 5.1 加密

| 场景 | 算法/协议 | 强度 | 合规依据 |
|------|---------|------|---------|
| **传输中（in-transit）** | TLS 1.3 + 国密 SM2/SM4 可选 | 高 | DSL 第 27 条、PDPA 安全义务 |
| **静态存储（at-rest）** | AES-256-GCM + KMS（HSM）密钥管理 | 高 | PIPL 第 51 条、PDPA 安全义务 |
| **敏感 PI 字段** | 字段级加密 + 密钥隔离（KMS + HSM） | 高 | PIPL 第 51(2)条 |
| **密钥轮换** | 90 天轮换 + 故障演练 | 中 | ISO 27001 A.10 |

### 5.2 去标识化 / 匿名化

| 技术 | 适用字段 | 效果 | 隐私风险 |
|------|---------|------|---------|
| **k-匿名 + l-多样性** | 行为聚合、品类标签 | 可去标识化（不可复原） | 低 |
| **差分隐私（ε=1, Laplace）** | 搜索关键词频次、统计量 | 不可复原 + 数学证明 | 极低 |
| **泛化（时/空）** | 位置轨迹（泛化到城市级） | 可去标识化 | 中 |
| **哈希脱敏（SHA-256 + 盐）** | 手机号、ID | 不可逆但可 join | 中（需控盐） |
| **联邦学习（梯度裁剪 + 加噪）** | 模型训练 | 原始数据不出境 | 极低 |
| **MPC（安全多方计算）** | 跨域特征交叉 | 不可复原 | 极低 |

> **关键判断**：AI 训练场景推荐**联邦学习 + 差分隐私 + 梯度裁剪**三层叠加，使"原始用户行为数据"原则上不出境，仅梯度/聚合统计量出境，大幅降低 PIPL 出境义务。

### 5.3 访问审计

- **全链路操作日志**：数据采集 → 脱敏 → 存储 → 训练 → 出境，全程可追溯
- **日志保留**：≥180 天（PIPL 第 51 条建议）
- **实时预警**：批量下载、异常访问、未授权训练调用 → 自动拦截 + 告警
- **审计输出**：季度合规报告（ISO 27001 / SOC2 / 中国等保 2.0 三级）
- **新加坡侧**：PDPC 7 大义务可审计 + 投诉通道日志

### 5.4 数据最小化

- **采集最小化**：仅采集训练必需字段，禁止"先采集后筛选"
- **存储最小化**：行为数据保留 ≤ 6 个月（除非 PIA 批准更久）
- **传输最小化**：出境白名单制（见 3.2），敏感字段不入白名单
- **模型最小化**：联邦学习/差分隐私下仅传输梯度，不传原始 PI
- **目的限定**：AI 训练用途单独说明，禁止"训练→营销"二次用途（须重新同意）

## 六、用户权利响应（跨境实现）

### 6.1 PIPL 第 44-47 条 + 新加坡 PDPA 对应

| 用户权利 | 法律依据 | 跨境实现方案 | SLA | 责任方 |
|---------|---------|-------------|------|--------|
| **查阅权** | PIPL 44 / PDPA 14 | 提供 PI 检索 API（含新加坡中台副本） | 15 天 | 中台 + 中国侧 IT |
| **更正权** | PIPL 46 / PDPA 14 | 双写一致性（中国 DB + SG 副本） | 15 天 | 中台 + 中国侧 IT |
| **删除权** | PIPL 47 / PDPA 22 | **级联删除**：中国侧 → SG 副本 → 模型权重影响评估（联邦下可忽略） | 30 天 | 中台合规团队 |
| **可携带权** | PIPL 45 / PDPA 21 | 导出 PI 数据包（CSV/JSON 双格式 + 训练贡献说明） | 30 天 | 中台 IT |
| **撤回同意** | PIPL 15 / PDPA 16 | 跨境同步撤回 → 停止 SG 侧训练 + 删除 SG 副本 | 15 天 | 中台合规 |
| **投诉权** | PIPL 52 / PDPA 28 | 双通道（中国 + SG）+ PDPC 投诉日志 | 15 天响应 | 双方法域合规 |

### 6.2 跨境级联删除技术架构

```
[中国用户行使删除] 
   │
   ▼
[中国侧 DB 软删除] 
   │ (消息队列 + 事件驱动)
   ▼
[新加坡中台订阅删除事件] 
   │
   ▼
[SG DB 软删除 + 模型权重影响评估] 
   │
   ▼
[删除确认回执] → 中国用户
   │
   ▼
[审计日志 + 留存证明]
```

> **联邦学习场景特殊处理**：梯度已聚合，单条 PI 贡献不可逆剔除，删除权实现为"停止后续训练调用" + 说明"已聚合梯度不可剔除"。

## 十、核心结论

1. **本项目必须走 PIPL 第 38 条三选一出境路径**，按数据量级 + 字段敏感性判定，默认推荐**安全评估（①）**；
2. **敏感 PI（人脸、位置、精确意图标签）须单独同意 + PIA + 强制加密**，缺失即行政处罚风险（2025.9 已开罚单）；
3. **技术架构推荐"联邦学习 + 差分隐私 + 梯度出境"** 三层叠加，使原始 PI 原则上不出境，将合规压力降至最低；
4. **跨境级联删除 + 双方法域合规档案** 是项目落地的硬性要求，须纳入 T+90 天验收；
5. **合规是"贯穿全生命周期"的持续工程**，须建立季度自查 + 第三方评估 + 监管对接机制。

**最终判定**：在 C1-C12 全部完成并通过验收前，**不得启动数据出境**。
